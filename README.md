## Project structure

Files in `lib/` are grouped by **what kind of file they are**:

```
lib/
  main.dart            App entry point (starts Firebase, then runs the app)
  app.dart             The root MaterialApp widget
  firebase_options.dart  Generated by FlutterFire — don't edit by hand

  models/      Plain data classes (Budget, Reminder, FinanceTransaction, ...)
  services/    Talk to Firebase and hold business logic (*_repository.dart)
  providers/   Riverpod providers that connect services to the screens
  screens/     One folder per app area (auth, budgets, calendar, ...)
  widgets/     Reusable UI pieces (buttons, cards, tiles, ...)
  routing/     Page routes and navigation (go_router)
  theme/       Colors, text styles, app theme
  utils/       Small helpers: dates, money, validators, constants, errors
  l10n/        Translations (app_en.arb, app_km.arb) + generated code
```

**How data flows:** a screen reads a **provider** → the provider calls a
**service** → the service reads/writes Firebase and returns **models**.

**Example — adding a budget:**
`screens/budgets/budget_form_screen.dart` → `providers/budget_providers.dart`
→ `services/budget_repository.dart` → `models/budget.dart`.
